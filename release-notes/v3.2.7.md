Much less data per check, and a command-line watcher that's gentler on a busy store.

**Already on 3.0 or later?** The app offers this update by itself within a day, or now from **Settings → Updates → Check for updates**. Installed with Scoop: `scoop update unifistockwatcher`.

**New here?** Download [`UnifiStockWatcher-Setup.exe`](https://github.com/jamesccupps/UnifiStockWatcher/releases/download/v3.2.7/UnifiStockWatcher-Setup.exe) (installs for your Windows user, no admin prompt) or the portable [`UnifiStockWatcher-win64.zip`](https://github.com/jamesccupps/UnifiStockWatcher/releases/download/v3.2.7/UnifiStockWatcher-win64.zip), or install it with [Scoop](https://scoop.sh):

```
scoop bucket add jamesccupps https://github.com/jamesccupps/scoop-bucket
scoop install jamesccupps/unifistockwatcher
```

If Windows shows *Windows protected your PC*, **More info** names the publisher, James Cupps; `SHA256SUMS.txt` lists every file's hash.

### Changed

- **A check now downloads only what changed.** Every check used to download the whole catalog, about 430 KB: some 600 MB a day at the default interval of a minute. The app now tells the store which copy of each page it already has, and the store sends only the pages that changed, so a check with no changes is a few kilobytes and takes about half as long. Each page is still downloaded in full at least every 10 minutes.

### Fixed

- **The command-line watcher kept asking a store that was refusing requests.** When the store turned away some of its pages (it was busy or rate limiting), the app waited longer before the next check, but the command-line watcher asked for each watched product's own page, every check. It now waits too, as the app does.

Running from source now needs Python 3.11 or newer (3.10 reached its end of life in October 2026). The Windows downloads include their own Python, so nothing changes for them.
